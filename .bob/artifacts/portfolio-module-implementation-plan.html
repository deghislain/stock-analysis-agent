1 · Overview & Scope

The portfolio module adds a persistence layer, a new UI tab, and a background scheduler on top of the existing single-report pipeline. It does not replace or break any existing functionality — every new API endpoint is additive and lives under a new /api/portfolios prefix.

RequirementWhat it means technically
Create / edit / delete portfolioCRUD REST endpoints + GUI forms
Add stock from a reportButton on Report.tsx; calls POST /api/portfolios/{id}/stocks
Portfolio tab with stock list & "View" buttonNew React page + GET /api/portfolios + stored report reference
Ranking by performanceComposite score already computed by the orchestrator; ranking is a sort

Historical rankingSnapshot table written after every refresh; exposed via API

2 · Persistence Strategy

The app currently uses an in-memory job store. For portfolios we need data to survive restarts, so we need a file-backed store. Two viable options:

OptionProsConsRecommendation
SQLite + SQLAlchemy Relational queries; easy ranking; mature; single file on disk More boilerplate; adds a dependency ✅ Recommended
JSON file (hand-rolled) Zero dependencies No transactions; concurrent write corruption; hard to query for rankings ❌ Avoid

Use SQLite via SQLAlchemy (sync, not async). The portfolio operations are not on the hot path and the extra complexity of async SQLAlchemy is not justified here. The database file lives at a path configured in config.py (e.g. /app/data/portfolios.db) and is mounted as a Docker volume alongside the PDF volume.

Add to requirements.txt:

sqlalchemy==2.0.36
# SQLite ships with Python's stdlib — no extra install needed

Add to .env.example and config.py:

DATABASE_URL=sqlite:////app/data/portfolios.db   # Docker default
# DATABASE_URL=sqlite:///portfolios.db           # bare-metal default (project root)

3 · Data Models

3.1 SQLAlchemy ORM tables

# backend/app/portfolio/models.py

from datetime import datetime
from sqlalchemy import (
    Column, String, Float, Integer, DateTime,
    ForeignKey, Text, UniqueConstraint
)
from sqlalchemy.orm import DeclarativeBase, relationship

class Base(DeclarativeBase):
    pass


class Portfolio(Base):
    __tablename__ = "portfolios"

    id          = Column(String, primary_key=True)   # UUID
    name        = Column(String(120), nullable=False)
    description = Column(Text, default="")
    created_at  = Column(DateTime, default=datetime.utcnow)
    updated_at  = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)

    stocks         = relationship("PortfolioStock", back_populates="portfolio",
                                  cascade="all, delete-orphan")
    ranking_snaps  = relationship("RankingSnapshot", back_populates="portfolio",
                                  cascade="all, delete-orphan")


class PortfolioStock(Base):
    __tablename__ = "portfolio_stocks"
    __table_args__ = (UniqueConstraint("portfolio_id", "ticker"),)

    id               = Column(String, primary_key=True)   # UUID
    portfolio_id     = Column(String, ForeignKey("portfolios.id"), nullable=False)
    ticker           = Column(String(10), nullable=False)
    company_name     = Column(String(200), default="")
    short_summary    = Column(Text, default="")       # executive_summary from latest report
    latest_report_id = Column(String, nullable=True)  # job_id of most recent completed report
    overall_score    = Column(Float, nullable=True)   # cached from latest report
    recommendation   = Column(String(10), nullable=True)  # "Buy" / "Hold" / "Sell"
    added_at         = Column(DateTime, default=datetime.utcnow)
    last_refreshed   = Column(DateTime, nullable=True)

    portfolio = relationship("Portfolio", back_populates="stocks")


class RankingSnapshot(Base):
    __tablename__ = "ranking_snapshots"

    id           = Column(String, primary_key=True)    # UUID
    portfolio_id = Column(String, ForeignKey("portfolios.id"), nullable=False)
    snapshot_at  = Column(DateTime, nullable=False)    # when snapshot was taken
    trigger      = Column(String(20), default="manual") # "manual" | "quarterly"

    entries = relationship("RankingEntry", back_populates="snapshot",
                           cascade="all, delete-orphan",
                           order_by="RankingEntry.rank")
    portfolio = relationship("Portfolio", back_populates="ranking_snaps")


class RankingEntry(Base):
    __tablename__ = "ranking_entries"

    id          = Column(String, primary_key=True)  # UUID
    snapshot_id = Column(String, ForeignKey("ranking_snapshots.id"), nullable=False)
    rank        = Column(Integer, nullable=False)
    ticker      = Column(String(10), nullable=False)
    overall_score      = Column(Float, nullable=True)
    fundamental_score  = Column(Float, nullable=True)
    technical_score    = Column(Float, nullable=True)
    sentiment_score    = Column(Float, nullable=True)
    recommendation     = Column(String(10), nullable=True)

    snapshot = relationship("RankingSnapshot", back_populates="entries")

⚠ Junior watch-out: latest_report_id is a job_id from the existing in-memory JobStore. The job store is cleared on restart, so after a restart the report JSON will be gone even though the portfolio record still holds an ID. For a production system you would persist report payloads too — but for this version, store the key report fields (score, recommendation, executive_summary) directly on PortfolioStock so the UI can render without needing the job store. The "View" button then re-triggers an analysis job on demand if the original job no longer exists.

4 · Performance Ranking Definition

The app already computes a 0–100 composite score per report:

overall_score = fundamental_score × 0.40
              + technical_score   × 0.40
              + sentiment_score   × 0.20

This is the single number used for ranking. Stocks are sorted descending by overall_score (highest score = rank 1). When two stocks have the same score (to two decimal places), they are sorted alphabetically by ticker as a stable tiebreaker.

Score rangeRecommendationMeaning in context
≥ 60BuyStrong positive signals across all three dimensions
40 – 59HoldMixed or neutral signals
< 40SellWeak or negative signals

Component scores and what drives them:

  • Fundamental score (0–100) — derived from P/E ratio, P/B ratio, EPS growth, debt-to-equity, profit margin, revenue growth, and dividend yield. Computed by FundamentalAnalyser.
  • Technical score (0–100) — derived from RSI(14), MACD crossover direction, and price position relative to SMA-20/50/200. Computed by TechnicalAnalyser.
  • Sentiment score (0–100) — derived from the positive/negative/neutral ratio of recent DuckDuckGo news headlines. Computed by SentimentAnalyser.

Ranking edge cases: A stock whose data could not be fetched at refresh time (network error, unknown ticker) receives overall_score = null. Null-score stocks are sorted to the bottom of the ranking and displayed with a "⚠ Data unavailable" badge, so they don't interfere with ranked stocks but remain visible to the user.

5.6 ranking.py

# backend/app/portfolio/ranking.py

from app.portfolio.models import PortfolioStock

def compute_ranking(stocks: list[PortfolioStock]) -> list[dict]:
    """
    Sort stocks by overall_score descending, then ticker ascending.
    Null-score stocks go to the bottom.
    Returns a list of dicts ready to be stored as RankingEntry rows.
    """
    def sort_key(s: PortfolioStock):
        score = s.overall_score if s.overall_score is not None else -1.0
        return (-score, s.ticker)

    sorted_stocks = sorted(stocks, key=sort_key)
    return [
        {
            "rank": i + 1,
            "ticker": s.ticker,
            "overall_score": s.overall_score,
            "recommendation": s.recommendation,
        }
        for i, s in enumerate(sorted_stocks)
    ]

5.7 scheduler.py

# backend/app/portfolio/scheduler.py

from apscheduler.schedulers.asyncio import AsyncIOScheduler
from apscheduler.triggers.cron import CronTrigger

scheduler = AsyncIOScheduler()

def start_scheduler(orchestrator, job_store, db_session_factory) -> None:
    """
    Register the quarterly refresh job and start the scheduler.

    Quarterly trigger: runs at 07:00 UTC on the first weekday after
    each quarter-end (Jan 2, Apr 1, Jul 1, Oct 1).
    Adjust dates to match when companies typically file earnings.
    """
    scheduler.add_job(
        _quarterly_refresh,
        CronTrigger(month="1,4,7,10", day="2", hour=7, minute=0),
        args=[orchestrator, job_store, db_session_factory],
        id="quarterly_refresh",
        replace_existing=True,
    )
    scheduler.start()

def stop_scheduler() -> None:
    if scheduler.running:
        scheduler.shutdown(wait=False)

async def _quarterly_refresh(orchestrator, job_store, db_session_factory) -> None:
    """
    For every stock in every portfolio: run a fresh analysis job,
    wait for completion, update PortfolioStock, then save a ranking snapshot.
    """
    from app.portfolio.crud import (
        list_portfolios, update_stock_from_report, save_ranking_snapshot
    )
    from app.portfolio.ranking import compute_ranking
    import uuid, asyncio

    with db_session_factory() as db:
        portfolios = list_portfolios(db)

    for portfolio in portfolios:
        # Fire one analysis job per unique ticker across this portfolio's stocks
        tickers = {s.ticker for s in portfolio.stocks}
        results: dict[str, dict] = {}

        for ticker in tickers:
            job_id = str(uuid.uuid4())
            job_store.create_job(job_id)
            await orchestrator.run(ticker, job_id)   # runs inline (background task)
            job = job_store.get_job(job_id)
            if job and job.status == "complete" and job.result:
                results[ticker] = job.result if isinstance(job.result, dict) \
                                  else job.result.model_dump()

        with db_session_factory() as db:
            for ticker, payload in results.items():
                update_stock_from_report(db, portfolio.id, ticker, payload)

            updated_portfolio = db.get(Portfolio, portfolio.id)
            ranked = compute_ranking(updated_portfolio.stocks)
            save_ranking_snapshot(db, portfolio.id, ranked, trigger="quarterly")

⚠ Scheduler concurrency: APScheduler's AsyncIOScheduler runs jobs in the same event loop as FastAPI/uvicorn. The quarterly refresh can be slow (N portfolios × M stocks × ~10 s per report). Cap the total number of concurrent analysis tasks with asyncio.Semaphore — otherwise the event loop starves the HTTP server during a refresh. A semaphore of 3 is a safe starting point.

7 · Report Refresh & Scheduling

7.1 What "quarterly refresh" means

Companies publish earnings quarterly (roughly Jan, Apr, Jul, Oct). The scheduler fires once per quarter on the first business day of those months at 07:00 UTC. It re-runs the full analysis pipeline for every stock in every portfolio using the existing Orchestrator.run() — no new code is needed in the analysis layer.

7.2 Refresh flow

Step 1 — Scheduler fires _quarterly_refresh()

Step 2 — For each unique ticker across all portfolios, create a new job and call orchestrator.run(ticker, job_id)

Step 3 — On completion, call crud.update_stock_from_report() to update overall_score, recommendation, short_summary, latest_report_id, and last_refreshed on each PortfolioStock row

Step 4 — Call ranking.compute_ranking() for each portfolio

Step 5 — Call crud.save_ranking_snapshot() with trigger="quarterly"

7.3 Manual refresh

POST /api/portfolios/{id}/refresh runs the same logic as the quarterly refresh but for a single portfolio, triggered by the user via the "↻ Refresh Now" button in the UI. Returns HTTP 202 immediately; the frontend can poll GET /api/portfolios/{id} and watch last_refreshed values change.

7.4 Concurrency guard

# In scheduler.py and the manual refresh route handler:
_REFRESH_SEMAPHORE = asyncio.Semaphore(3)

async with _REFRESH_SEMAPHORE:
    await orchestrator.run(ticker, job_id)

This ensures at most 3 analysis jobs run in parallel during a refresh, preventing the event loop from being starved by a large portfolio.

8 · Edge Cases & Validation Rules

SituationRule
Adding a ticker that already exists in a portfolioReturn HTTP 409 Conflict. Message: "Ticker AAPL is already in this portfolio."
Adding a stock from a report that is not yet completeReturn HTTP 422. The frontend "Add to Portfolio" button must only be enabled when status === "complete".
Portfolio name empty or only whitespacePydantic min_length=1 + backend strips and re-validates.
Portfolio with 0 stocks rankedRanking endpoint returns an empty list — not an error.
Stock data unavailable during refreshSet overall_score = null, recommendation = null. Add a warning but continue refresh for other stocks. Do not abort the whole portfolio refresh.
Deleting a portfolio that is currently being refreshedSQLite row-level locking handles this — the refresh's session will complete its transaction before the delete succeeds, or vice-versa. Acceptable for v1.
Ticker is valid format but no longer tradesThe existing GET /api/validate/{ticker} endpoint catches this before any report is generated. The "Add to Portfolio" button only appears after a successful report, so this case is already filtered.

Report PDF path no longer valid after restartThe "View" button on a portfolio stock only links to the report page (uses job_id from job store). After restart the job store is empty. Handle the 404 in the frontend as described in §6.6.
Max portfolios per userNo hard limit in v1 (single-user local tool). Document this assumption.

10 · Junior-Developer Watch-Outs

1. SQLite and Docker volumes

The database file must live in a Docker volume, not inside the container image. Add a second named volume db_data to docker-compose.yml mounted at /app/data. If you forget this the database resets on every docker compose up --build.

2. Never call Orchestrator.run() directly from a route handler

The manual refresh endpoint (POST /api/portfolios/{id}/refresh) must return HTTP 202 immediately and run the refresh as a BackgroundTask, exactly like POST /api/analyse does. If you await orchestrator.run() inside the route handler the request will time out for large portfolios.

3. check_same_thread=False is required for SQLite

SQLAlchemy's SQLite dialect refuses cross-thread access by default. You must pass connect_args={"check_same_thread": False} when creating the engine. This is safe because SQLAlchemy manages its own connection pool and serialises access correctly.

4. The job store is ephemeral; the database is persistent

These are two separate stores. The job store holds in-progress and recently completed analysis results in RAM. The database holds portfolio metadata and cached scores on disk. Copy the fields you need (score, recommendation, summary) from the job result into the database immediately after a job completes — don't rely on the job store being there later.

5. APScheduler and uvicorn workers

If you ever run uvicorn with --workers 2 (multiple processes), each worker will start its own scheduler and the quarterly refresh will run twice simultaneously. For v1 (single worker, local use) this is not a problem. Document it as a known limitation.

6. Ranking snapshots are immutable once written

Never update an existing RankingSnapshot. Always insert a new one. This preserves the full history. The current live ranking is always derived on-the-fly from the current overall_score values on PortfolioStock rows.

7. TypeScript types must mirror Python schemas exactly

Every field in schemas/portfolio.py must have a corresponding field in types/portfolio.ts. If you add a field to the Python schema and forget to add it to TypeScript, the UI will silently ignore it. Use Optional in Python and | null in TypeScript for nullable fields — and check both sides whenever you change a schema.

8. The "View" button after a restart

The job store is in-memory and clears on restart. Store the key report fields in the database (score, recommendation, summary). For the "View" button, always check if the job still exists before navigating. If not, offer to regenerate — don't show a broken page.
